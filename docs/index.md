## Phase 4. Technical Modification
Below are the listed steps involved in my technical modification:

- In excel, I create a fictitious store csv file(`stores_data_prepared.csv`) which had columns named storeid and storetype.This was created because the fact_sales table did have a store_id column which did not connect to any dimension table in the data warehouse.
- Made a copy of `dw_create_case.py` and `etl_case.py` (`dw_create_arnold.py` and `elt_arnold.py`).
- Modified the above copies to perform the actions listed in the next two points.
- Created a table in the warehouse named dim_stores using columns identify in stores_data_prepared.csv
- Uploaded rows in `stores_data_prepared.csv` to dim_stores.
- The results was a dim_stores table with 4 rows and 2 columns.
- Verified if the dim_stores table was created and filled with data successfully by reviewing verification information in the project.log file and using the DuckDB extension in VS Code to view the dim_stores table.

Even though updating the various Python scripts to implement the changes was pretty straightforward because I had an example to follow, I still had to be meticulous about making sure every row in dim_stores was unique and that every transaction in fact_sales was linked to a row in dim_stores.

## Phase 5. Custom Project
Building on the changes made in Phase 4, I customized the example project by making the following updates:

- I copied the custom data files created in module 3—`customers_data_prepared.csv`, `products_data_prepared.csv`, and `sales_data_prepared.csv`—into a new folder named `prepared_2`. These data files contain the same columns as the example project except for additonal columns indicated in the changes below.
- Using the information in my custom `sales_data_prepared.csv`, I created a new CSV file called `campaigns_data_prepared.csv` (created in Excel). This file contains campaign data related to sales and includes two columns: `campaign_id` and `campaign_type`.
- Since I was using the custom data from Module 3, which contained additional columns compared to the example project, I updated `dw_create_arnold.py` to delete the existing data warehouse and create an updated one. I also modified `elt_arnold.py` to load the additional data into the newly created tables.
- I added a function to `dw_create_arnold.py` to create the `campaigns` table with the columns `campaign_id` and `campaign_type`.
- I updated the function that creates the `customers` table to include the columns `first_name`, `last_name`, `customer_type`, and `customer_tenure_years`. The previous `name` column was removed.
- I updated the function that creates the `products` table to include the columns `name`, `unit_cost`, `average_quality_rating`, and `quality_rating`, replacing the previous `product_name` column.
- I modified the function that creates the `sales` table to include the `transaction_time_minutes` column.
- Star schema was enforced in data warehouse using primary and foreign keys to link dimension and facts. The "id" columns in the tables served this purpose.
- I updated `elt_arnold.py` to load data from the new CSV files into the updated data warehouse tables.
- Finally, I reviewed the `project.log` file and used the DuckDB extension to check the dimension and fact tables to confirm that all changes were successfully applied after running `dw_create_arnold.py` and `elt_arnold.py`.

The result of our project was:
- An artifacts folder which holds our data warehouse.
- A fact_sales table linked to our dimension tables via foreign keys.
- A dim_customers table linked to fact_sales via customer_id.
- A dim_products table linked to fact_sales via product_id.
- A dim_stores table linked to fact_sales via store_id.
- A dim_campaigns table linked to fact_sales via campaign_id.
- A project.log detailing the project and specifics:
  - PASS:dim_customers has 200 rows
  - PASS: dim_products has 100 rows
  - PASS: fact_sales has 2207 rows
  - PASS: dim_stores has 4 rows
  - PASS: dim_campaigns has 4 rows

Potential challenges or pitfalls to watch out for include:

- Following the correct column naming conventions and paying attention to case sensitivity.
- Making sure the column order matches when inserting data from the CSV files into the data warehouse.
- Remembering that every time `dw_create_arnold.py` is executed, a new empty data warehouse is created, so any existing data will need to be reloaded.
